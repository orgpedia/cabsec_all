AoB issue codes

What each issue in the amendments (aob-ammend_) and consolidated versions (aob-rules_) studios means.

Reading an amendment (ops check)

A change quotes words that are not in the notification. Each change's quoted strings (its expect, old and new, and the headings in its path) should appear word for word in the notification's text.

Usually the model paraphrased or misread the quote. Sometimes the change is right and the file's text is wrong: a scan whose lines came out of order, or an "after X, add Y" written as a substitution whose new text joins X and Y.

Do: if the quote is wrong, correct it at the Changes level. If the change is right, dismiss with a note.

A clause says something "shall be" inserted, omitted or substituted, but no change was read from it.

Do: add the missing change at the Changes level, or dismiss if the clause makes no change to the Rules (its short title, its commencement).

The changes are not numbered 1, 2, 3… in order, or one refers to a change that is not an earlier insertion or replacement ("the heading as so substituted" pointing at the wrong change).

Do: fix the numbering or the reference at the Changes level.

The model was not sure which part a change's path means: the path could fit more than one.

Do: check the path against the notification and the version; make it name the part fully, or dismiss.

For information: the quoted text runs across a page break. Running headers and page numbers sit in the middle of it, and may have crept into the quote.

Do: nothing, unless the change's new text has a page header or number in it.

For information: a new ministry or department heading has no Hindi name in brackets, which headings usually carry, e.g. "(KRISHI MANTRALAYA)".

Do: nothing if the notification prints none; otherwise check the change's new text has it.

The model named text that could not be found where it said, so the item was not linked to its words.

Do: set it again by picking its words on the page, or dismiss if the item is not needed.

The model gave a label or a value the flow does not allow (a kind of change it does not know, a date that is not a date). It was left out.

Do: add the item by hand if it matters.

Applying a change to the Rules (the states)

A change's path leads nowhere in the Rules as they stood before it: no part with that number or heading. Its op was left out, so nothing was changed.

Usually the path is misread (a heading's spelling, the wrong department letter or schedule), or the version before printed the part differently. Look at the version named under "See".

Do: correct the path at the Changes level. If the Rules before it are wrong, fix that version instead.

A change's path fits more than one part ("entry 1" under a ministry with two departments), or an insertion has no single part to go after or before. Its op was left out.

Do: add the missing step (the department, the part) to the path at the Changes level.

The part the change acts on does not read as the notification quotes it ("for entry 5, which reads …"). Its op was left out.

Do: if the path picks the wrong part, correct it. If the quote is misread, correct the expect. If the Rules before it were printed differently, dismiss with a note.

The words to substitute or omit are not in the part the path leads to. Its op was left out.

Do: correct the old words or the path at the Changes level.

The change omits a part that is already omitted. Its op was left out.

Do: check the path; an earlier amendment may have omitted it, or the path names the wrong part.

The change refers to the part an earlier change made ("the heading as so substituted"), but its path does not lead there. Its op was left out.

Do: correct the path or the reference at the Changes level.

A kind of change the patcher cannot apply. Its op was left out.

Do: correct the change's kind at the Changes level, or tell the developer.

The change applies to the version printed before it, but not to the Rules as built up from the start (the states). So the states differ there from that version, because an earlier difference was left open, or because there is no version before this amendment to check it against.

Do: usually nothing here. Settle the earlier differences first (series in order); this goes away when they are. If it stays, read it like the same code without "state_".

Checking against the consolidated versions

The version an amendment was applied to already prints what the amendment makes, where it makes it (the heading it gives, the parts it inserts), so the amendment's changes could not be applied. The version is probably later than its listed "upto": the website's file was replaced by a later one (1_Upload_915, listed upto 299, was made after amendment 300 and prints its rename).

Do: open the version under "See" and check. If it is later than listed, set it aside (the versions flow's exclude, with the reason); otherwise dismiss with a note.

Two versions in a row read the same, though the amendment between them changes the Rules. One of them is probably listed under the wrong "upto" (1_Upload_913, listed upto 300, is 1_Upload_910, upto 301, word for word).

Do: find which one holds the amendment's change; set the other aside (the versions flow's exclude), or dismiss with a note.

A part reads differently in the consolidated version than in the Rules built from the version before plus this amendment. The words that differ are shown, the version's text second. Look at both versions under "See".

It is one of these: a change misread (fix the change); a version misread (fix its words at the Words level); a typo printed for years and corrected later (ask for the typo script); or the compilers' own correction with no amendment making it.

Do: fix what is misread. For the compilers' correction, use Take the version's text, so the Rules follow the version from here on. Dismiss, with a note, only what is not worth tracking.

A part is in the consolidated version but not in the Rules built from the version before plus this amendment.

Usually: a change that inserts it was missed or read with the wrong path; the version is misread (a footnote or a heading read as a part); or the compilers added it with no amendment.

Do: add or fix the change; fix the version's reading; or Take the version's text if the version is right and no amendment made it.

A part is in the Rules built from the version before plus this amendment, but not in the consolidated version.

Usually: a change that omits it was missed; a change inserted it in the wrong place (it shows as extra here and missing elsewhere); or the version is misread.

Do: fix the change or the version's reading; Take the version's text if the version is right and no amendment made it.

For information: a ministry's or department's Hindi name reads differently in the consolidated version than in the Rules built from the version before plus this amendment. The English names agree, so the parts are the same; only the Hindi name in brackets differs ("KORPORATE KARYA MANTRALAYA" and "CORPORATE KARYA MANTRALAYA").

Usually a misreading on one side, a spelling the compilers changed, or a Hindi name an amendment renamed.

Do: fix what is misread. If the version is right, use Take the version's text; otherwise dismiss with a note. Hindi names are not counted in the report's differences or drift.
