AoB issue codes

What each issue in the amendments (aob-ammend_) and consolidated versions (aob-rules_) studios means. A code's first word is the stage it was found at, so settle the stages in order: a change misread (1) fails to apply (2, 3) and makes differences (4).

old
the consolidated version printed before the amendment, e.g. 1_Upload_883.pdf.
amendment
the notification for Series N, e.g. 1_Upload_367.pdf (Series 322).
new
the consolidated version printed after it, e.g. 1_Upload_881.pdf.
expected new
old with the amendment applied.
the states
the Rules built from the start (Series 301) through every amendment in turn, without the versions in between. In Phase C, where there are no versions in between, this is the only chain.

1. read_: reading the amendment, on its own

A change quotes words that are not in the notification. Each change's quoted strings (its expect, old and new, and the headings in its path) should appear word for word in the notification's text.

Usually the model paraphrased or misread the quote. Sometimes the change is right and the file's text is wrong: a scan whose lines came out of order, or an "after X, add Y" written as a substitution whose new text joins X and Y.

Do: if the quote is wrong, correct it at the Changes level. If the change is right, dismiss with a note.

A clause says something "shall be" inserted, omitted or substituted, but no change was read from it.

Do: add the missing change at the Changes level, or dismiss if the clause makes no change to the Rules (its short title, its commencement).

The changes are not numbered 1, 2, 3… in order, or one refers to a change that is not an earlier insertion or replacement ("the heading as so substituted" pointing at the wrong change).

Do: fix the numbering or the reference at the Changes level.

The model was not sure which part a change's path means: the path could fit more than one.

Do: check the path against the notification and the version; make it name the part fully, or dismiss.

For information: the quoted text runs across a page break. Running headers and page numbers sit in the middle of it, and may have crept into the quote.

Do: nothing, unless the change's new text has a page header or number in it.

For information: a new ministry or department heading has no Hindi name in brackets, which headings usually carry, e.g. "(KRISHI MANTRALAYA)".

Do: nothing if the notification prints none; otherwise check the change's new text has it.

The model named text that could not be found where it said, so the item was not linked to its words.

Do: set it again by picking its words on the page, or dismiss if the item is not needed.

The model gave a label or a value the flow does not allow (a kind of change it does not know, a date that is not a date). It was left out.

Do: add the item by hand if it matters.

2. old_: applying a change to old

A change's path leads nowhere in old: no part with that number or heading. The change was left out, so nothing was changed.

Usually the path is misread (a heading's spelling, the wrong department letter or schedule, a note or an item step left out), or old printed the part differently. Look at the version named under "See".

Do: correct the path at the Changes level. If old is misread, fix its words instead.

A change's path fits more than one part of old ("entry 1" under a ministry with two departments), or an insertion has no single part to go after or before. The change was left out.

Do: add the missing step (the department, the part) to the path at the Changes level.

The part of old the change acts on does not read as the notification quotes it ("for entry 5, which reads …"). The change was left out.

Do: if the path picks the wrong part, correct it. If the quote is misread, correct the expect. If old printed it differently, dismiss with a note.

The words to substitute or omit are not in the part of old the path leads to. The change was left out.

Do: correct the old words or the path at the Changes level (the words may be in the entry's note: add a note step).

The change omits a part that old shows omitted already. The change was left out.

Do: check the path; an earlier amendment may have omitted it, or the path names the wrong part.

The change refers to the part an earlier change made ("the heading as so substituted"), but its path does not lead there. The change was left out.

Do: correct the path or the reference at the Changes level.

A kind of change the patcher cannot apply. The change was left out.

Do: correct the change's kind at the Changes level, or tell the developer.

Old already prints what the amendment makes, where it makes it (the heading it gives, the parts it inserts), so the amendment's changes could not be applied. Old is probably later than its listed "upto": the website's file was replaced by a later one (1_Upload_915, listed upto 299, was made after amendment 300 and prints its rename).

Do: open old under "See" and check. If it is later than listed, set it aside (the versions flow's exclude, with the reason); otherwise dismiss with a note.

Old and new read the same, though the amendment between them changes the Rules. One of them is probably listed under the wrong "upto", usually old (1_Upload_913, listed upto 300, is 1_Upload_910, upto 301, word for word).

Do: find which one holds the amendment's change; set the other aside (the versions flow's exclude), or dismiss with a note.

3. states_: applying a change to the states

The change applies to old, but not to the states, so the states differ there from old: an earlier difference was left open, or there is no version before this amendment to check it against.

Do: usually nothing here. Settle the earlier differences first (series in order); this goes away when they are. If it stays, read it like the same code with old_: the states may hold a misreading of the version they start from.

4. new_: expected new against new

A part reads differently in expected new than in new. The words that differ are shown, new's text second. Look at both versions under "See".

It is one of these: a change misread (fix the change); a version misread (fix its words at the Words level); a typo printed for years and corrected later (ask for the typo script); or the compilers' own correction with no amendment making it.

Do: fix what is misread. For the compilers' correction, use Take the version's text, so the states follow new from here on. Dismiss, with a note, only what is not worth tracking.

A part of new is missing from expected new.

Usually: a change that inserts it was missed or read with the wrong path; a version is misread (a footnote or a heading read as a part); or the compilers added it with no amendment.

Do: add or fix the change; fix the version's reading; or Take the version's text if new is right and no amendment made it.

A part is in expected new but not in new.

Usually: a change that omits it was missed; a change inserted it in the wrong place (it shows as extra here and missing elsewhere); or a version is misread.

Do: fix the change or the version's reading; Take the version's text if new is right and no amendment made it.

Several headings under one part are numbered differently in new than in expected new, all moved by the same amount ("ministry 24 → 23 … department 50 → 49"). Their names agree; only the numbers differ. They are listed as one issue, not one each.

Usually: the compilers renumbered them in this version with no amendment doing it (filling a number a change left empty); or an amendment that renumbers them was missed.

Do: if an amendment renumbers them, add or fix it. Otherwise Take the version's text: the states take the version's numbers from that amendment on. A heading whose number differs on its own (lost, or moved by another amount) stays its own issue under new_text_differs.

For information: a ministry's or department's Hindi name reads differently in new than in expected new. The English names agree, so the parts are the same; only the Hindi name in brackets differs ("KORPORATE KARYA MANTRALAYA" and "CORPORATE KARYA MANTRALAYA").

Usually a misreading on one side, a spelling the compilers changed, or a Hindi name an amendment renamed.

Do: fix what is misread. If new is right, use Take the version's text; otherwise dismiss with a note. Hindi names are not counted in the report's differences or drift.
